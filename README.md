# 會議室預約看板

公司內部同仁用的會議室預約網頁：在瀏覽器選會議室、日期與整點時段，填上姓名即可預約，系統會自動擋下時段衝突。**純前端、無後端、無登入**，資料只存在瀏覽器的 `localStorage`。

## 功能清單

- 預約 3 間會議室（A、B、C），可選日期與整點起訖時段（08:00–18:00）
- 填寫預約人姓名後送出
- 顯示「所選日期」的所有預約
- 時段衝突檢查：同會議室、同日期、時段重疊即拒絕並提示
  - 時段為半開區間 `[start, end)`，所以 10–11 與 11–12 **不**衝突
- 資料存 `localStorage`，重新整理不消失（資料不存在或格式損壞時回退為空清單）
- 取消預約：每筆預約附「取消」按鈕，先 `confirm()` 確認才刪除
- 匯出 CSV：下載所選日期的預約（會議室、時段、預約人）；檔頭含 BOM，Excel 可正確顯示中文；以 `= + - @` 開頭的欄位會加單引號防公式注入；該日無預約時不下載並提示
- 深色模式：標題列右側的按鈕可切換淺色／深色配色，選擇會記在 `localStorage`（key 為 `meetingRoomTheme`），純外觀、不影響預約資料

### 非目標

登入與權限、後端與資料庫、多人即時同步、Email／通知皆**不做**。完整需求與驗收標準見 [spec.md](spec.md)。

## 如何開啟使用

不需要安裝、建置或啟動伺服器：

1. 取得專案（`git clone` 或直接下載）。
2. 用瀏覽器雙擊開啟 `index.html`。

> 資料綁定在「瀏覽器 + 開啟的網址」，換瀏覽器或清除網站資料後預約會消失；儲存的 key 為 `meetingRoomBookings`。

## 如何執行測試

沒有測試工具鏈，也不需要 npm。用瀏覽器雙擊開啟 `test.html`，頁面會載入 `app.js` 並自動執行衝突判定測試（`isOverlap`、`findConflict`），頂部顯示「通過 N 項／共 N 項」（綠底為全數通過、紅底為有失敗），下方表格列出每項的預期值、實際值與結果。

涵蓋情境：完全相同、完全錯開、空清單、前後部分重疊、互相包含、緊鄰時段（應允許）、不同會議室、不同日期。

介面功能（建立、取消、匯出、深色模式切換、重新整理後資料仍在）則依 [spec.md](spec.md) 的驗收標準在 `index.html` 手動驗證。

## 檔案結構

```
meeting-room-board/
├── index.html   # 主頁面：介面、樣式、儲存／繪製／表單／取消／匯出 CSV／深色模式切換
├── app.js       # 衝突判定：isOverlap、findConflict（純函式，供頁面與測試共用）
├── test.html    # 衝突判定的瀏覽器內測試頁
├── spec.md      # 需求來源（功能、非目標、驗收標準）
├── CLAUDE.md    # 給 Claude Code 的開發規範
└── README.md    # 本文件
```

## 開發規範

- 檔案限定為 `index.html`、`app.js`、`test.html` 三檔，不再拆分其他檔案
- 以一般 `<script src="app.js">` 載入（不用 ES module），確保雙擊即可開啟
- 禁止外部框架與函式庫（不用 CDN、不用 npm），只用原生 Web API
- 介面文字與程式註解一律使用繁體中文
- 修改前先讀 `spec.md`，範圍有疑問時以其「非目標」與「驗收標準」為準，不自行擴充功能
